# 04 模块边界与阶段规划

## 模块边界原则

每个模块需要回答三个问题：

- 它做什么。
- 它依赖什么。
- 它对外提供什么接口。

模块内部可以演进，但对外边界应稳定。Renderer 页面通过 Preload API 使用能力，不直接依赖本地实现细节。

## 核心模块边界

### Knowledge Base

职责：

- 管理知识资料。
- 维护文档索引。
- 提供检索和 RAG 问答。

不负责：

- 管理代码仓库。
- 管理情报抓取。
- 管理 Agent 权限。

对外能力：

- 文档导入。
- 索引状态。
- 检索。
- RAG 问答。
- 来源引用。

### Code Repository

职责：

- 管理本地代码仓库。
- 读取 Git 状态。
- 分析代码结构。
- 生成结构图和报告。
- 支持代码问答。

不负责：

- 存储通用知识库文档。
- 执行高风险系统命令。
- 替代完整 IDE。

对外能力：

- 仓库列表。
- Git 状态。
- 搜索。
- 结构解析。
- 依赖图。
- 代码上下文检索。

### Agent Runtime

职责：

- 组织用户消息、上下文和工具调用。
- 调用 LLM Provider。
- 执行授权工具。
- 记录任务日志和结果。

不负责：

- 直接读写所有本地资源。
- 绕过模块权限访问数据。
- 维护每个业务模块的内部索引。

对外能力：

- 会话。
- 模型选择。
- 工具调用。
- 任务执行。
- 日志记录。
- 结果沉淀。

### 情报中心接入

职责：

- 管理 local-intel 服务状态。
- 展示情报数据。
- 提供配置入口。
- 查看报告和调度状态。

不负责：

- 重写 local-intel 抓取逻辑。
- 重写摘要、翻译和观察雷达逻辑。

对外能力：

- 启动、停止、重启。
- 健康检查。
- 数据读取。
- 报告查看。
- 配置跳转。

### Local Music

职责：

- 管理本地音乐文件。
- 提供播放控制。
- 维护播放队列和元数据。

不负责：

- 在线音乐服务。
- 复杂音频编辑。
- 第一阶段语音助手主流程。

对外能力：

- 扫描音乐库。
- 播放控制。
- 播放列表。
- 元数据读取。

## 阶段规划

### 第一阶段：总控台骨架与核心工作流

重点模块：

- Home Dashboard。
- Knowledge Base。
- Code Repository。
- Agent Chat。
- Agent Management。
- 情报中心接入。

目标：

- 定义统一分层架构。
- 明确 `window.api.*` 边界。
- 复用 local-intel。
- 建立知识库 RAG 和代码仓库分析的主流程。
- 明确数据存储边界。

### 第二阶段：体验完善与跨模块联动

重点能力：

- Dashboard 汇总更完整。
- Agent 可以调用知识库、代码仓库和情报中心工具。
- 知识库和代码仓库的搜索结果可以互相引用。
- 情报条目可以沉淀到知识库。
- 代码分析结果可以生成 PlantUML 图。

### 第三阶段：音乐、语音和小组件

重点能力：

- Local Music 完善播放和音乐库管理。
- 语音助手接入 ASR/TTS。
- 小组件扩展机制。
- 快速命令和系统状态。

## 优先级建议

最高优先级：

- Electron 分层架构。
- Preload API 设计。
- Service Manager。
- Knowledge Base。
- Code Repository。
- Agent Runtime。
- local-intel 接入。

中优先级：

- Dashboard 聚合体验。
- Agent Management。
- 数据存储治理。
- PlantUML 图生成。

后续优先级：

- Local Music 深化。
- 语音助手。
- 小组件市场或插件化。

## 风险与约束

- 模块多，第一版必须控制范围，避免每个模块都同时深入实现。
- LLM Provider 不应散落在页面或业务模块中。
- 代码仓库分析不能只依赖 LLM，需要本地解析工具支撑。
- 情报中心已有成果应优先复用。
- Secrets 和本地命令执行必须有清晰边界。
