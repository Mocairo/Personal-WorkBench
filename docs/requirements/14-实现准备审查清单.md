# 14 实现准备审查清单

## 目标

本清单用于判断当前需求文档和 PlantUML 结构图是否已经足够支撑后续进入 Electron 桌面客户端实现。它不是实现计划，而是审查入口。

## 产品范围审查

- 桌面控制台定位已经明确：本地优先的个人工作台。
- 第一阶段核心模块已经明确：Home Dashboard、Knowledge Base、Code Repository、Agent Chat、Agent Management、情报中心接入。
- 扩展模块已经明确：Local Music、Voice Assistant、小组件。
- 明确不做 Electron 脚手架、不写实现代码、不重写 local-intel。

证据：

- `01-产品愿景与范围.md`
- `02-页面与功能清单.md`
- `04-模块边界与阶段规划.md`

## 架构边界审查

- Renderer 页面层、复合组件层、Preload API、主进程、Service Manager、本地能力和数据层已经分层。
- Renderer 不直接访问 Node、文件系统、Git、数据库、命令和 Secrets。
- `window.api.*` 命名空间已经覆盖主要模块。
- IPC channel 命名和返回结构已有统一约定。

证据：

- `03-技术架构说明.md`
- `06-Preload-API与IPC契约.md`
- `overall-architecture.puml`
- `ipc-and-services.puml`
- `preload-api-contract.puml`

## 进入实现时的建议顺序

1. 建立 Electron 主窗口、当前页面宿主、页面注册表、快捷键切换器、设置页和任务中心。
2. 建立 Preload API、IPC Router、统一 `ApiResult` 和任务事件。
3. 建立 App SQLite、配置存储和 Secrets Store。
4. 建立 Service Manager，并优先接入 local-intel。
5. 建立 Knowledge Base 导入、索引和检索。
6. 建立 Code Repository 扫描、Git、搜索和结构解析。
7. 建立 Agent Runtime、LLM Provider Adapter 和工具权限。
8. 建立 Dashboard 聚合。
9. 扩展 Local Music、Voice Assistant 和小组件。

## 当前可进入实现的判定

如果审查者接受当前页面范围、分层架构、API 命名空间、数据边界、权限策略和 local-intel 接入策略，则当前文档和 `.puml` 图已经足够支撑进入桌面客户端实现。
