# 01 产品愿景与范围

## 产品定位

这是一个本地优先的个人桌面控制台，使用 Electron 作为桌面客户端框架。它不是单一聊天应用、单一知识库或单一代码仓库工具，而是一个把个人知识、项目代码、情报信息、Agent 能力、音乐播放和小工具统一起来的本地工作台。

核心体验是：打开一个桌面客户端，就能看到今日工作入口、知识沉淀、代码项目状态、情报摘要、Agent 任务和本地服务状态。

## 核心目标

1. 管理自己的知识库，包括 Markdown、PDF、网页剪藏、Obsidian Vault、标签、向量索引和问答检索。
2. 可视化和管理本地代码仓库，包括 Git 状态、目录树、代码结构、依赖关系、搜索、报告和代码问答。
3. 接入已有情报中心，复用 `D:\python_code\local-intel\.worktrees\reliability-foundation` 的抓取、摘要、翻译、观察雷达和调度能力。
4. 提供 Agent Chat 与 Agent Management，用统一入口管理 LLM、工具调用、任务队列、权限和执行记录。
5. 提供本地音乐播放器、语音助手和其他小组件的扩展入口，让控制台成为长期演进的个人桌面系统。

## 典型使用场景

- 启动客户端后，在 Home Dashboard 查看今日情报、最近项目、知识库索引状态和 Agent 任务。
- 进入 Knowledge Base，把本地笔记、PDF 或 Obsidian Vault 导入索引，然后用 LLM 基于来源引用回答问题。
- 进入 Code Repository，选择本地仓库，查看 Git 状态、目录结构、依赖图和代码统计，并向 LLM 提问。
- 在 Agent Chat 中让 Agent 使用知识库、代码仓库、情报中心或文件系统工具执行任务。
- 在情报中心查看已有 local-intel 的今日情报、观察雷达、来源状态和运行日志。
- 在 Local Music 播放本地音乐，并为后续语音助手、歌词、音乐整理留下接口。

## 第一阶段范围

第一阶段优先设计以下模块：

- Home Dashboard
- Agent Chat
- Knowledge Base
- Agent Management
- Code Repository
- 情报中心接入

Local Music、语音助手和其他小组件在第一阶段定义入口、边界和依赖，不作为主线深挖。

## 明确不做

- 不把第一版写成完整实现计划。
- 不创建 Electron 项目脚手架。
- 不直接重写现有 local-intel。
- 不把每个页面写到像素级 UI 细节。
- 不在每个模块里各自散落 LLM API 调用；LLM 必须通过统一 Provider Adapter。
- 不让 Renderer 页面直接访问文件系统、Git、数据库或系统命令。

## 成功标准

第一版文档完成后，应能回答以下问题：

- 这个桌面控制台是什么，第一阶段做什么，不做什么。
- 每个页面入口的职责、依赖和边界是什么。
- Electron 的 Renderer、Preload、主进程、本地服务和数据层如何分工。
- 知识库、代码仓库、Agent、情报中心分别如何流转数据。
- 现有 local-intel 如何以独立 Python 服务形式被 Electron 接入。
