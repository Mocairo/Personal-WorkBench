# 09 代码仓库详细需求

## 目标

Code Repository 模块用于管理和理解本地代码仓库。它不是完整 IDE，而是面向项目分析、结构可视化、Git 状态、代码检索和 LLM 辅助理解的工作台。

## 仓库管理

第一阶段支持：

- 添加本地仓库路径。
- 展示仓库名称、路径、默认分支。
- 展示 Git 是否可用。
- 展示最近打开时间。
- 移除仓库引用。

移除仓库引用不删除本地文件。

## Git 能力

Git Adapter 提供：

- 当前分支。
- 工作区状态。
- 最近提交。
- diff 摘要。
- remote 信息。
- tag 和 release 摘要。

第一阶段只读 Git 信息，不默认执行提交、推送、重置、删除分支等修改操作。

## 文件树和搜索

File Walker 负责读取目录树。

规则：

- 遵守 `.gitignore`。
- 默认忽略 `node_modules`、`.git`、`dist`、`build`、`.venv`、缓存目录。
- 大文件只显示元数据，不直接加载全文。
- 二进制文件只显示类型和大小。

ripgrep 用于：

- 文件名搜索。
- 正文搜索。
- 符号附近文本定位。

## 代码结构解析

Tree-sitter 用于抽取：

- 函数。
- 类。
- 方法。
- import/export。
- 常量。
- 类型定义。
- 文件级符号。

解析结果写入 Code Index。不同语言可以逐步扩展，第一阶段优先 TypeScript/JavaScript、Python、Markdown。

## 依赖分析

依赖分析分两层：

- 目录和文件层依赖。
- package / import 层依赖。

候选来源：

- `package.json`
- `pyproject.toml`
- Python import。
- TypeScript import/export。
- README 和配置文件。

输出：

- 模块依赖图。
- 入口文件候选。
- 高耦合文件。
- 未识别依赖。

## 代码问答

代码问答流程：

1. 用户选择仓库或文件范围。
2. Query Planner 判断需要搜索、结构索引还是 Git 上下文。
3. Code Search 找到相关文件和符号。
4. Context Builder 截取代码片段。
5. LLM Code Assistant 生成解释、总结或建议。
6. 返回引用文件、行号和相关符号。

回答要求：

- 必须引用文件路径。
- 涉及具体代码时尽量引用行号。
- 信息不足时说明还需要查看哪些文件。
- 不直接执行修改。

## 结构图生成

支持生成：

- 模块关系图。
- 文件依赖图。
- 主要调用流程图。
- 数据流草图。
- PlantUML 类图或组件图草稿。

图生成应可追溯到输入文件和分析来源。LLM 可以辅助整理，但基础关系应优先来自本地解析工具。

## 与 Agent 的关系

Agent 可用工具：

- `codeRepo.list`
- `codeRepo.gitSummary`
- `codeRepo.search`
- `codeRepo.getFile`
- `codeRepo.getSymbolTree`
- `codeRepo.ask`
- `codeRepo.generateDiagram`

修改文件、运行命令、Git 写操作属于高权限工具，需要额外授权。

## 错误与恢复

错误场景：

- 路径不存在。
- 不是 Git 仓库。
- Git 命令不可用。
- 文件过大。
- Tree-sitter 不支持语言。
- 索引任务中断。

恢复策略：

- 非 Git 仓库仍可作为普通代码目录扫描。
- 不支持语言仍可做文本搜索。
- 大文件跳过并进入扫描报告。
- 索引失败可以按文件重试。

## 第一阶段验收口径

- 仓库管理和 Git 只读边界明确。
- 文件树、搜索、Tree-sitter、依赖分析职责明确。
- 代码问答和结构图生成有来源引用。
- Agent 调用代码仓库的权限边界明确。
