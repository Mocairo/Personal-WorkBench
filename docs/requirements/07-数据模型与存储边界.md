# 07 数据模型与存储边界

## 目标

数据模型用于约束各模块的数据归属，避免知识库、代码仓库、情报中心、Agent、音乐和设置互相污染。第一阶段不需要锁定完整数据库 DDL，但需要明确核心实体、关系和存储位置。

## 存储分层

### App SQLite

由 Electron 应用管理，保存桌面控制台自身状态。

适合保存：

- 应用设置摘要。
- 最近打开页面。
- 最近项目。
- 后台任务。
- Agent 会话和运行日志。
- 工具权限策略。
- 音乐元数据索引。
- 知识库文档元数据。
- 代码仓库元数据。
- local-intel 状态摘要和报告索引。

不保存：

- API Key 明文。
- local-intel 的原始情报主数据。
- 大体积文件正文。
- 真实音乐文件。
- 真实代码仓库内容。

### Vector Store

由知识库和代码仓库共用抽象边界，但需要用 collection 或 namespace 隔离。

适合保存：

- 知识库 chunk embedding。
- 代码片段 embedding。
- 情报条目 embedding。
- 元数据引用。

不保存：

- Secrets。
- 无来源引用的孤立回答。

### 文件系统

保存原始内容：

- Markdown。
- PDF。
- Obsidian Vault。
- 代码仓库。
- 音乐文件。
- local-intel reports。
- local-intel logs。

### local-intel SQLite

继续由 local-intel 管理。Electron 只读取或聚合，不接管其 schema。

## 核心实体

### AppSetting

字段建议：

- `key`
- `value`
- `scope`
- `updatedAt`

用于保存非敏感配置。敏感配置只保存引用或 Provider 名称。

- `status`

## Secrets 边界

Secrets Store 管理：

- LLM API Key。
- GitHub Token。
- MiMo Key。
- OpenAI-compatible Key。
- 代理配置中的敏感字段。

Renderer 只能看到：

- Provider 是否配置。
- Provider 显示名称。
- 配置是否可用。
- 脱敏后的 key 摘要，例如 `sk-...abcd`。

## 数据生命周期

- 原始文件由用户目录管理，应用只保存引用。
- 索引可重建，不能成为唯一数据来源。
- 任务日志可按时间清理。
- Agent 会话需要用户明确删除。
- Secrets 删除后相关 Provider 立即不可用。
- local-intel 数据由 local-intel 自己的配置和生命周期管理。

## 第一阶段验收口径

- 能区分 App SQLite、local-intel SQLite、Vector Store 和文件系统职责。
- 每个核心模块都有明确实体。
- Agent、知识库、代码仓库和音乐数据不会混在同一概念里。
- Secrets 不进入 Renderer 和普通数据库表。
