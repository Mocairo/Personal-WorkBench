# 13 安全、权限与错误处理

## 目标

桌面控制台会接触本地文件、代码仓库、系统命令、API Key、LLM Provider 和本地服务。安全设计必须前置，避免 Renderer、Agent 或小组件绕过边界直接执行高风险操作。

## 安全边界

核心边界：

- Renderer 不能直接访问 Node API。
- Renderer 不能直接访问文件系统。
- Renderer 不能直接读取 Secrets。
- Renderer 不能直接运行命令。
- Agent 不能绕过 Tool Registry。
- Tool Executor 不能绕过 Permission Gate。
- Service Manager 不能暴露裸进程控制给页面。

## 权限分级

### Level 0：只读 UI

示例：

- 查看 Dashboard。
- 查看状态。
- 查看配置摘要。

### Level 1：只读数据访问

示例：

- 搜索知识库。
- 搜索代码。
- 查看 Git 状态。
- 查看情报摘要。
- 查看音乐播放状态。

### Level 2：本地应用写入

示例：

- 保存笔记。
- 创建播放列表。
- 保存 Agent 配置。
- 写入应用设置。

### Level 3：服务控制

示例：

- 启动 local-intel。
- 停止 local-intel。
- 运行情报更新。
- 启动索引任务。

### Level 4：本地文件或命令修改

示例：

- 修改代码文件。
- 删除文件。
- 执行 shell 命令。
- Git commit、push、reset。

第一阶段默认开放 Level 0 和 Level 1。Level 2 需要模块内明确动作。Level 3 和 Level 4 需要额外确认或配置授权。

## Agent 工具权限

每个工具定义需要包含：

- `toolId`
- `name`
- `description`
- `permissionLevel`
- `inputSchema`
- `outputSchema`
- `defaultPolicy`
- `auditLog`

默认策略：

- 只读工具可在受限范围内使用。
- 写入工具需要 Agent 配置允许。
- 服务控制工具需要用户动作触发或明确授权。
- 文件修改和命令执行默认禁用。

## 路径访问策略

允许访问的路径来源：

- 用户手动选择的知识库目录。
- 用户手动添加的代码仓库。
- 用户手动添加的音乐目录。
- 配置好的 local-intel 路径。
- 应用自己的数据目录。

禁止默认访问：

- 任意系统目录。
- Secrets 文件。
- 浏览器用户数据。
- 未经用户添加的项目路径。

## Secrets 策略

Secrets 只能由主进程管理。Renderer 可请求：

- Provider 是否已配置。
- Provider 显示名称。
- 脱敏 key 摘要。

Renderer 不获得：

- 完整 API Key。
- Token 明文。
- `.env` 原文。

## 错误处理

错误结构统一：

- 错误码。
- 用户可读消息。
- 可选详细信息。
- 是否可重试。
- 日志引用。

用户界面展示：

- 发生了什么。
- 用户可以做什么。
- 是否可以重试。
- 是否需要打开设置或日志。

日志记录：

- 模块。
- 操作。
- 参数摘要。
- 权限判断。
- 错误码。
- 堆栈或命令 stderr。

日志不得记录 API Key 明文。

## 诊断入口

建议提供统一诊断页：

- Electron 应用状态。
- Preload API 可用性。
- App SQLite 可用性。
- Vector Store 可用性。
- local-intel 状态。
- LLM Provider 状态。
- Git/ripgrep/Tree-sitter 可用性。
- 音乐目录状态。

诊断页只显示脱敏信息。

## 第一阶段验收口径

- 权限分级覆盖只读、写入、服务控制、命令执行。
- Agent 工具不能绕过权限。
- 路径访问必须来自用户授权或应用目录。
- Secrets 不进入 Renderer。
- 错误和日志结构统一。
