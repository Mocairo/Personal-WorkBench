# 03 技术架构说明

## 总体分层

系统采用清晰的 Electron 分层架构：

```text
Renderer 页面层
  -> Renderer 复合组件层
  -> Preload API 安全边界
  -> Electron 主进程 IPC
  -> Service Manager / 本地能力模块
  -> 数据层 / LLM Provider / 外部 API / 本地服务
```

Renderer 页面不直接访问文件系统、Git、数据库、系统命令或 API Key。所有本地能力都通过 Preload 暴露的 `window.api.*` 进入主进程，再由主进程分发到对应服务。

## Renderer 页面层

页面层负责导航、布局、状态展示和用户交互。主要页面包括：

- Home Dashboard
- Agent Chat
- Knowledge Base
- Agent Management
- Code Repository
- Local Music
- 情报中心
- 其他小组件

页面层只依赖 Renderer 内部状态和 Preload API，不直接导入 Node 系统能力。

## Renderer 复合组件层

复合组件层承载跨页面工作区组件，例如：

- 知识库工作区。
- 代码仓库工作区。
- Agent 聊天面板。
- 任务队列面板。
- 情报卡片和观察雷达。
- 音乐播放控制条。
- 服务状态组件。

复合组件可以组合多个 `window.api.*` 接口，但仍然不直接接触系统能力。

## Preload API

Preload 是 Renderer 与本地能力之间的安全边界。建议暴露以下 API 命名空间：

```text
window.api.kb
window.api.codeRepo
window.api.agent
window.api.intel
window.api.music
window.api.voice
window.api.system
```

职责划分：

- `window.api.kb`：知识库导入、索引、检索、问答。
- `window.api.codeRepo`：仓库扫描、Git 状态、代码搜索、结构图生成。
- `window.api.agent`：聊天、模型选择、工具调用、任务日志。
- `window.api.intel`：local-intel 状态、报告、配置入口。
- `window.api.music`：音乐库扫描、播放控制、播放列表。
- `window.api.voice`：ASR、TTS、语音助手扩展。
- `window.api.system`：窗口、文件选择、服务健康状态和通用本地任务。

## Electron 主进程

主进程负责本地能力调度：

- IPC Router。
- Service Manager。
- File System Adapter。
- Git Adapter。
- Process Adapter。
- LLM Provider Adapter。
- App SQLite 访问。
- Secrets 管理。
- 窗口生命周期。

主进程应把每类能力封装为独立 adapter 或 service，避免 IPC handler 直接堆业务逻辑。

## Service Manager

Service Manager 统一管理本地后台能力：

- 启动、停止、重启 local-intel。
- 检查 Python 服务健康状态。
- 管理索引任务。
- 管理后台扫描任务。
- 管理本地模型服务或外部 Provider 连接状态。

第一版最重要的服务是 `local-intel` 接入。它保留为独立 Python 服务，Electron 只负责管理和展示。

## 数据层

数据边界建议如下：

- App SQLite：应用状态、页面配置、任务日志、Agent 历史、音乐元数据、最近项目。
- local-intel SQLite：继续由 local-intel 管理情报数据。
- Vector Store：知识库和代码仓库语义索引。
- 文件系统：Markdown、Obsidian Vault、PDF、代码仓库、音乐文件、报告文件。
- 配置文件：本地路径、模型配置、服务配置。
- Secrets Store：API Key、Token 和敏感配置。

## LLM Provider Adapter

所有 LLM 调用都通过统一 Provider Adapter，不在各模块中直接调用模型 API。

候选 Provider 类型：

- OpenAI-compatible Provider。
- MiMo Provider。
- Local Model Provider。
- Embedding Provider。
- ASR/TTS Provider。

统一适配层应负责模型名称、base URL、API Key、超时、重试、流式输出、错误归一化和成本/日志记录。

## 知识库 RAG 架构

知识库数据流：

```text
文档导入
  -> 文本抽取
  -> Chunk
  -> Keyword Index
  -> Embedding
  -> Vector Store
  -> Hybrid Search
  -> Context Builder
  -> LLM Answer
  -> Source Citation
```

回答必须保留来源引用，避免把知识库问答变成不可追溯的纯聊天。

## 代码仓库分析架构

代码仓库数据流：

```text
选择本地仓库
  -> Git CLI
  -> File Walker
  -> ripgrep
  -> Tree-sitter
  -> Dependency Analyzer
  -> Code Index
  -> LLM Code Assistant
  -> 结构图 / 报告
```

代码仓库模块应优先使用稳定本地工具，不把全部理解压力交给 LLM。

## 安全原则

- Renderer 不直接访问 Node API。
- Preload 只暴露白名单能力。
- IPC channel 按模块命名和校验参数。
- 工具调用必须经过权限检查。
- Secrets 不进入 Renderer 状态。
- 本地命令执行必须记录来源、参数和结果。
